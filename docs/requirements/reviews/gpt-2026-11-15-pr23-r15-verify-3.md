## R15V3-02 — BLOCKING: a non-Markdown prefix restores R15V2-01

Source: `xtask/src/secrets/credentials.rs:174`, `:225`, `:322`.
`markdown_value` infers an inline-code opener from any earlier backtick on the
line, without checking whether it belongs to an actual Markdown span. In a
Rust source string, an unrelated earlier backtick makes a later backtick
inside the password look like a closing delimiter. The classifier again sees
only the standalone placeholder, not the complete literal password.

Reproduce in an otherwise passing minimal repository with an ordinary
open-commercial baseline manifest. The construction is fragmented so this
report does not publish a complete literal credential fixture:

```bash
python3 - "$PROBE/notes.rs" <<'PY'
from pathlib import Path
import sys
prefix = 'Server=database.internal;Uid=operator;'
key = 'Pwd'
value = '<EXAMPLE_PASSWORD_WITH_BACKTICK_AND_SPACE>'
text = ('fn main() { let marker = "' + chr(96) + '"; '
        'let connection = "' + prefix + key + '=' + value + ';"; '
        'let _ = (marker, connection); }\n')
Path(sys.argv[1]).write_text(text)
PY
git -C "$PROBE" add notes.rs
"$XTASK" --repo "$PROBE" --policy "$CANDIDATE" provenance
```

Observed: **exit 0**, `PASS: provenance/secrets/data (D-56)`. Changing only
the earlier marker from a backtick to a vertical bar causes **exit 1** with
`local-connection-password`. Both source variants independently compile with
Rust 2024 and execute an assertion that the connection contains the complete
literal password. The earlier string is unrelated to that password; it is
not a Markdown delimiter. A text variant with an escaped Markdown opener also
passes incorrectly; an unmatched two-backtick opener does not hide the value.

The analogous source-context fixture also passes at `112de8d`; therefore this
is **not** claimed as a regression versus round 14. It is BLOCKING because it
directly restores R15V2-01's fixed behavior: an unquoted, placeholder-prefixed
password containing an internal backtick and space is truncated before literal
classification. No new credential family, decoder or data format is involved.
Preserve the passing Markdown controls while ensuring source strings and
escaped openers cannot shorten a real credential value.
