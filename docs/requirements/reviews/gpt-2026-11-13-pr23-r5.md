### 1. R5-01 — High — STRUCTURAL: any OUT_DIR substring disables computed-include checking

**Locations:** `xtask/src/rust_policy.rs:719`, specifically `:727`.
**Related:** R4-01, ADV23R4-02; NFR-10.
**Reviewer test:** `out_dir_substring_exempts_tracked_include`.

Place the helper at `spikes/OUT_DIR-helper.rs`. Use this complete engine build.rs:

```rust
#![forbid(unsafe_code)]
include!(concat!("../../spikes/", "OUT_DIR-helper.rs"));
fn main() { emit(); }
```

The include path is a constant pointing at a tracked source file. There is no
environment lookup and no generated file. Nevertheless, `Modules::include`
exempts any computed expression whose token spelling contains `OUT_DIR`, silently
omitting the helper. Its physical spikes location removes the fallback scan too.
Both policy checks accept it; actual Cargo runs the helper and emits the Python
link instruction.

**Control:** replace only the invocation with
`include!("../../spikes/OUT_DIR-helper.rs");`. The same checker now reports the
helper's Python instruction. The submitted unresolved-include test only uses
`concat!("sr", "c/x.rs")`; it never tests the permissive substring branch.

**Suggested change:** recognize an explicitly supported generated-file expression
structurally, with an actual `env!("OUT_DIR")` base and a path that cannot escape
it. Resolve constant concatenations or reject them. A matching string/identifier
must not grant a generation exemption. Add this tracked-file counterexample and
an allowed genuine generated-file control.

### 2. R5-02 — High — STRUCTURAL: renaming the include macro hides a compiled helper

**Locations:** `xtask/src/rust_policy.rs:760` and `:693`.
**Related:** R4-01, ADV23R4-02; NFR-10.
**Reviewer test:** `include_macro_alias_is_unchecked`.

Place the helper at `spikes/helper.rs`. Use this complete engine build.rs:

```rust
#![forbid(unsafe_code)]
use std::include as load;
load!("../../spikes/helper.rs");
fn main() { emit(); }
```

Rust imports macros through `use`. Cargo therefore compiles the included helper
and runs its emit function. The walker recognizes only macro paths ending in the
literal identifier `include`. Its fallback token scan sees just a string in
`load!(...)`, reports no unresolved include and discovers no helper. Both policy
checks accept this fixture, and Cargo emits the prohibited link instruction.

**Control:** replace the import and aliased invocation with direct
`include!("../../spikes/helper.rs");`. The checker flags the helper immediately.
The submitted tests only call the builtin by its original name.

**Suggested change:** resolve or reject imports that rename filesystem-loading
builtins, including their use inside scanned macro bodies. Do not treat a macro's
unrecognized surface name as proof that it cannot load source. A conservative
restriction is acceptable if alias resolution is outside the supported policy
syntax. Add this real Cargo fixture and the direct-include control.

### 3. R5-03 — High — STRUCTURAL: Cargo member globs use a different language from the policy matcher

**Locations:** `xtask/src/rust_policy.rs:539`–`:546`; `xtask/src/util.rs` glob matcher.
**Related:** R4-01; unsafe-scope/ADR 0001.
**Reviewer test:** `workspace_bracket_glob_member_is_unchecked`.

Change the common workspace member list to:

```toml
members = ["crates/*", "spikes/[m]ember"]
```

Create `spikes/member/Cargo.toml` using the common package manifest with its name
changed to `member`. Its complete src/lib.rs is:

```rust
macro_rules! lowered {
    ($lint:ident) => {
        #[allow($lint)]
        pub fn value() -> i32 {
            let n = 1;
            let p = &n as *const i32;
            unsafe { *p }
        }
    };
}
lowered!(unsafe_code);
```

Cargo's member-glob expansion recognizes `[m]` as a character class and compiles
this member. The shared policy glob supports `*` and `?`, but treats brackets
literally. The member is omitted from production_packages, remains spikes-exempt,
and never receives the required forbid check. Source and manifest checks both
return **[]**, while real Cargo successfully compiles the unsafe pointer access
under the inherited deny lint.

**Control:** change only `spikes/[m]ember` to `spikes/member`. The checker then
reports the missing `#![forbid(unsafe_code)]` on that member. The submitted member
regression uses a literal path and cannot expose this language mismatch.

**Suggested change:** use Cargo-compatible expansion for `members` and `exclude`,
separate from CODEOWNERS' deliberately narrower syntax, or fail closed on member
patterns the checker cannot interpret. Do not silently classify their possible
matches as standalone spikes. Add the bracket-glob/Cargo compilation fixture.

### 4. R5-04 — High — STRUCTURAL: patch resolution drops build-dependency execution context

**Locations:** `xtask/src/rust_policy.rs:449`–`:464`, `:485`–`:494`.
**Related:** ADV23R4-02; NFR-10.
**Reviewer test:** `patched_build_dependency_loses_build_context`.

Append this to the common root manifest:

```toml
[patch.crates-io]
helper = { path = "crates/helper" }
```

Append this to the engine package manifest:

```toml
[build-dependencies]
helper = "0.0.0"
```

Create `crates/helper/Cargo.toml` using the common package manifest, renamed to
`helper`. Its src/lib.rs contains `#![forbid(unsafe_code)]` followed by the common
emit function. Engine build.rs is:

```rust
#![forbid(unsafe_code)]
fn main() { helper::emit(); }
```

The helper is selected and scanned, but only as ordinary production code. The
build-dependency string is skipped because it is not a table, and the patch path
is independently queued with `build = false`. Nothing connects those edges to
mark the helper as executing inside a build script. Both policy checks accept it;
Cargo resolves the local patch offline and emits the prohibited Python instruction.
This case does not depend on the spikes exemption or unusual filenames.

**Control:** change only the engine dependency to
`helper = { path = "../helper" }` in `[build-dependencies]`. The checker now flags
the helper as build-script code. The submitted direct path-dependency regression
exercises only that working form, despite the implementation's broader patch claim.

**Suggested change:** propagate build context through resolved dependency edges,
including local patch/replace targets, rather than collecting their paths as
unrelated ordinary packages. Alternatively, enforce the prohibited Cargo link
instruction rule wherever its producer occurs in production Rust. Keep trusted
analysis from executing submitted build scripts. Add the patched-build-dependency
fixture and its direct-path control.
