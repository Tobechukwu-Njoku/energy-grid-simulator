## 2. Executive Summary of Remaining False Negatives

While the rewrite to Rust `cargo xtask` resolves all 18 initial findings, an adversarial robustness audit across the six requested functional areas revealed **9 remaining false negatives (ADV23R-01 through ADV23R-09)**. These gaps permit non-compliant inputs to bypass attribution detection, allow global lint overrides via Cargo configuration, accept invalid provider separation in review evidence, run outdated policy checks in CI, and miss standard API keys or restricted datasets.

## 3. Detailed Findings (ADV23R-01 .. ADV23R-09)

### ADV23R-01: Unicode Mathematical Minus Sign (`U+2212`) in `Co−Authored−By` Bypasses Attribution Detection

- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Unicode Normalization
- **File & Line Citation:** `.githooks/attribution-patterns.regex:2`, `xtask/src/attribution.rs:146-203`
- **Description:**  
  Pattern 1 in `.githooks/attribution-patterns.regex` uses `[\-\x{2010}-\x{2015}]` to match hyphens in trailers (e.g. `Co-Authored-By:`). The character class includes ASCII `-` (0x2D) and Unicode dashes U+2010 through U+2015 (hyphen, non-breaking hyphen, figure dash, en dash, em dash, horizontal bar).
  However, mathematical minus sign `−` (`U+2212`), widely used on Mac keyboards and rendered identically in typography, is outside this range.
  Furthermore, `attribution::normalise()` applies Unicode NFKC normalization, which does **not** decompose or map `U+2212` to ASCII `-`. `fold_confusable()` also does not include `U+2212`.
- **Minimal Test Input:**
  ```text
  Co−Authored−By: Claude <noreply@anthropic.com>
  ```
  *(where `−` is `\u{2212}`)*
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_attribution_unicode_minus -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 1 (Unicode minus): line='Co−Authored−By: Claude <noreply@anthropic.com>', matched=false
  ```
  `p.matches_line(...)` returned `false`. The trailer is accepted without error.
- **Suggested Fix:**  
  In `xtask/src/attribution.rs`, map `\u{2212}`, `\u{fe63}` (small hyphen-minus), and `\u{ff0d}` (fullwidth hyphen-minus) to `-` in `fold_confusable()`, or expand the regex character class in `.githooks/attribution-patterns.regex` to include `\x{2212}`.

### ADV23R-02: Cyrillic Small Letter 'м' (`U+043C`) in `Gemini` (`Geмini`) Bypasses Attribution Detection

- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Unicode Normalization
- **File & Line Citation:** `xtask/src/attribution.rs:169`, `.githooks/attribution-patterns.regex:4`
- **Description:**  
  In `xtask/src/attribution.rs`, `fold_confusable()` includes mappings for Cyrillic and Greek look-alikes. Line 169 includes:
  ```rust
  'М' | 'Μ' | 'Ꮇ' => 'M',
  ```
  It maps uppercase Cyrillic 'М' (`U+041C`) to 'M', but omits lowercase Cyrillic 'м' (`U+043C`). Because NFKC does not map Cyrillic letters to Latin, any footer or trailer referencing `Gemini` with Cyrillic small 'м' passes through `normalise()` as `Ge\u{043c}ini`. Pattern 2 requires ASCII `gemini`.
- **Minimal Test Input:**
  ```text
  Generated with Geмini
  ```
  *(where `м` is `\u{043c}`)*
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_attribution_cyrillic_small_m -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 2 (Cyrillic small m): line='Generated with Geмini', matched=false
  ```
  `p.matches_line(...)` returned `false`.
- **Suggested Fix:**  
  Add `'м' => 'm'` to `fold_confusable()` in `xtask/src/attribution.rs`.

### ADV23R-03: Leading AI Emojis (Sparkles `✨`, Brain `🧠`, Computer `💻`) and Emojis Preceding Trailers Evade Attribution Scanners

- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Emojis & Markup Stripping
- **File & Line Citation:** `.githooks/attribution-patterns.regex:2, 4`, `xtask/src/attribution.rs:205-235`
- **Description:**  
  Pattern 2 includes `(?:\x{1F916}\x{FE0F}?\s*)?` allowing the robot emoji `🤖` (`U+1F916`) before "Generated with". However:
  1. Automated AI tools (e.g. Gemini, Cursor, Copilot, ChatGPT) commonly prefix footers with sparkles (`✨` `U+2728`), lightning (`⚡`), brain (`🧠`), or computer (`💻`).
  2. Pattern 1 (`Co-Authored-By`) does not include `\x{1F916}` or any emoji pattern.
  3. `strip_markup()` in `attribution.rs` strips Markdown punctuation, comment tokens, and quote markers, but does not strip emojis from line beginnings.
  As a result, prepending `✨` to a footer or `🤖` to a `Co-Authored-By:` trailer causes the anchor `^\s*` to fail match.
- **Minimal Test Inputs:**
  - Input 1: `✨ Generated with Claude Code`
  - Input 2: `🤖 Co-Authored-By: Claude <noreply@anthropic.com>`
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_attribution_emojis -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 3 (Emojis): sparkles matched=false, robot matched=false
  ```
  Both inputs returned `false` and bypassed detection.
- **Suggested Fix:**  
  In `xtask/src/attribution.rs`, update `strip_markup()` or `candidates()` to strip Unicode emoji characters (`\p{Extended_Pictographic}`) from candidate line prefixes.

### ADV23R-04: `Co-Authored-By: GitHub Copilot` Without Email and Spaced Trailer Prefix Evade Pattern 1

- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Trailer Syntax
- **File & Line Citation:** `.githooks/attribution-patterns.regex:2, 4`
- **Description:**  
  In Pattern 1 of `.githooks/attribution-patterns.regex`:
  1. The direct model identifier list after `-by:` includes `copilot`, `claude`, `gemini`, etc., but does **not** include `github copilot`. If a commit specifies `Co-Authored-By: GitHub Copilot` without an email address, it falls through to the second regex branch which requires `<...email...>`. Because no email is present, it is accepted.
  2. Pattern 1 requires `[\-\x{2010}-\x{2015}](?:by|with):`, mandating a hyphen before "by". If an author formats the trailer as `Co-authored by: Claude` (space before "by"), Pattern 1 does not match. Pattern 2 also does not match because it checks `generated|written|authored` without "co-".
- **Minimal Test Inputs:**
  - Input 1: `Co-Authored-By: GitHub Copilot`
  - Input 2: `Co-authored by: Claude <noreply@anthropic.com>`
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_attribution_copilot_and_space -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 4 (GitHub Copilot): matched=false, (Co-authored by): matched=false
  ```
- **Suggested Fix:**  
  In Pattern 1, include `(?:github[\s_-]*)?copilot` in the primary model list, and permit optional spaces or hyphens before `by|with` in trailer headers.

### ADV23R-05: Commit Author and Committer Headers in Git Commit Objects are Uninspected

- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Commit Inspection Scope
- **File & Line Citation:** `xtask/src/attribution.rs:504-523`
- **Description:**  
  In `xtask/src/attribution.rs`, `scan_range()` processes each commit in `base..head` by executing `git cat-file commit <sha>`. Line 506 parses the message:
  ```rust
  let message = raw
      .windows(2)
      .position(|pair| pair == b"\n\n")
      .map_or(&raw[..0], |index| &raw[index + 2..]);
  ```
  It inspects only bytes following the first `\n\n` (the commit message body).
  The Git commit object header (lines preceding `\n\n`) contains `author <name> <email>` and `committer <name> <email>`. If an agent or contributor creates a commit authored by an AI identity (e.g. `git commit --author="Claude <claude@anthropic.com>"`) with a clean commit message, `cargo xtask attribution` reports 0 findings.
  This violates D-52: "No AI watermarking, ever... accountability rests with the human owner."
- **Minimal Test Input:**
  A Git commit object where `author Claude Code <claude@anthropic.com>` is set in the commit header and commit message is `feat: implement solver stub`.
- **Command Run:**
  ```bash
  cargo xtask attribution --base origin/main --head <sha>
  ```
- **Observed Output:**
  ```text
  scanned 1 commit(s), 0 added line(s), title=no, body=no
  PASS: attribution policy (D-52)
  ```
- **Suggested Fix:**  
  In `attribution::scan_range()`, inspect the `author` and `committer` lines of `cat-file commit` for known AI model names and vendor email domains (`@anthropic.com`, `@openai.com`, `@google.com`, `*bot*@*`).

### ADV23R-06: Extensionless Cargo Configuration (`.cargo/config`) Bypasses `check_manifests` Lint Checks

- **Severity:** CRITICAL
- **Area:** Unsafe Code & Lint Policy / Cargo Configuration
- **File & Line Citation:** `xtask/src/rust_policy.rs:299-304`
- **Description:**  
  Cargo supports configuration files named either `.cargo/config.toml` or `.cargo/config` (extensionless). Both have equal precedence and are loaded automatically by Cargo during local builds and CI.
  In `xtask/src/rust_policy.rs`:
  ```rust
  let is_cargo_config = path == ".cargo/config.toml" || path.ends_with("/.cargo/config.toml");
  if is_cargo_config {
      let text = std::fs::read_to_string(ctx.repo.join(&path))?;
      findings.extend(check_cargo_config(&path, &text));
  }
  ```
  The predicate only checks for filenames ending in `/.cargo/config.toml`.
  If a PR introduces `.cargo/config` containing `[build]\nrustflags = ["-A", "unsafe_code"]` or `rustflags = ["--cap-lints=allow"]`, `check_cargo_config()` is never invoked. The workspace-level `unsafe_code = "deny"` lint is overridden during compilation without triggering a CI failure.
- **Minimal Test Input:**
  Creating a file `.cargo/config` with content:
  ```toml
  [build]
  rustflags = ["-A", "unsafe_code"]
  ```
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_cargo_config_without_extension -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 6 (.cargo/config without extension): is_cargo_config=false
  ```
  `check_manifests()` reports `PASS: manifests` and completely overlooks `.cargo/config`.
- **Suggested Fix:**  
  In `xtask/src/rust_policy.rs`, expand `is_cargo_config`:
  ```rust
  let is_cargo_config = path == ".cargo/config"
      || path == ".cargo/config.toml"
      || path.ends_with("/.cargo/config")
      || path.ends_with("/.cargo/config.toml");
  ```

### ADV23R-07: Provider Separation Parses Only Model Suffix, Allowing Same-Vendor Models to Approve Review Gates

- **Severity:** HIGH
- **Area:** Independent Review Gate / Provider Separation (ADR 0001, NFR-3.AC3)
- **File & Line Citation:** `xtask/src/review_gates.rs:45-52, 110-113`
- **Description:**  
  ADR 0001 (lines 117–124) and NFR-3.AC3 mandate independent review evidence from a **different provider** (e.g. Anthropic author vs OpenAI reviewer).
  In `xtask/src/review_gates.rs`:
  ```rust
  fn provider(value: &str) -> Option<String> {
      let last = value.rsplit('/').next()?.trim();
      let word: String = last
          .chars()
          .take_while(|c| c.is_alphanumeric() || *c == '-')
          .collect();
      (!word.is_empty()).then(|| word.to_lowercase())
  }
  ```
  `provider()` splits on `/` and takes only the **last** segment.
  If a review header specifies:
  `- Author role/provider: Anthropic / Claude-Sonnet`
  `- Reviewer role/provider: Anthropic / Claude-Opus`
  `header.author` becomes `"claude-sonnet"` and `header.reviewer` becomes `"claude-opus"`.
  The check `author != reviewer` evaluates to `true`. The vendor ("Anthropic") is discarded, allowing two models from the same vendor to satisfy the independent review gate.
- **Minimal Test Input:**
  Review report header:
  ```markdown
  # Review
  - Author role/provider: Anthropic / Claude-Sonnet
  - Reviewer role/provider: Anthropic / Claude-Opus
  - Reviewed head: 1111111111111111111111111111111111111111
  - Verdict: approved
  ```
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_review_gate_provider_separation -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 7 (Provider separation): author='claude-sonnet', reviewer='claude-opus', differ=true
  ```
  `evaluate()` accepts the evidence as valid independent review.
- **Suggested Fix:**  
  Normalize model identifiers to their provider organization (`anthropic`, `openai`, `google`, `human`) and compare provider organizations rather than raw trailing model strings.

### ADV23R-08: CI Reads Policy from Stale Base Commit Rather Than Main Tip, and Falls Back to Untrusted PR HEAD

- **Severity:** HIGH
- **Area:** CI Execution / Trusted Policy Base
- **File & Line Citation:** `.github/actions/trusted-policy/action.yml:17, 30`, `.github/workflows/ci.yml:28-65`
- **Description:**  
  1. In `.github/actions/trusted-policy/action.yml`:
     ```bash
     base="$(jq -r '.pull_request.base.sha // .before // empty' "$GITHUB_EVENT_PATH")"
     ```
     In GitHub Actions, `.pull_request.base.sha` corresponds to the base branch commit when the PR was opened or last synchronized. If `main` has progressed with new security fixes, dependency bans, or review gate updates, an unrebased PR is evaluated against the obsolete policy of its old base, not the current `main` branch.
  2. If the base commit lacks `xtask/Cargo.toml` (e.g. before PR #23 merges into main), line 30 falls back to:
     ```bash
     git worktree add --detach --quiet "$trusted" HEAD
     ```
     This executes the untrusted PR's own `xtask` binary and policy configuration.
  3. Jobs `rust-linux` and `rust-macos` in `.github/workflows/ci.yml` execute `cargo clippy` and `cargo nextest` directly against the PR checkout without comparing against `trusted-policy`.
- **Minimal Test Input:**
  A PR whose base branch commit does not contain `xtask/Cargo.toml` or whose base commit is behind `main`.
- **Observed Result:**
  Line 30 of `action.yml` outputs `::warning::bootstrap: the base has no xtask policy yet; this revision's seed is used`, executing untrusted code from PR `HEAD`.
- **Suggested Fix:**  
  In `trusted-policy/action.yml`, fetch and verify `refs/remotes/origin/main` rather than `.pull_request.base.sha`. If `main` has no trusted policy, fail closed or require manual coordinator dispatch rather than executing untrusted `HEAD`.

### ADV23R-09: Standard User OpenAI Keys (`sk-`) Evade Secret Scan, and Manifest Array Syntax (`files = [...]`) Bypasses Research-Only Data Check

- **Severity:** HIGH
- **Area:** Provenance Gate / Secrets and Research-Only Data (D-56)
- **File & Line Citation:** `xtask/src/repository.rs:241-326, 105-120, 398-443`, `xtask/policy/repository.toml:19-27`
- **Description:**  
  1. In `SECRET_RULES` in `xtask/src/repository.rs`:
     ```rust
     SecretRule { name: "OpenAI-style key", prefix: "sk-proj-", min_tail: 32, tail: token_char }
     ```
     Only project-scoped OpenAI keys (`sk-proj-`) are detected. Standard user OpenAI API keys starting with `sk-` (followed by 48+ alphanumeric characters) are not detected.
  2. In `manifest_datasets()` in `xtask/src/repository.rs`:
     ```rust
     let files = ["filename", "relative_path", "local_name"].iter().filter_map(|key| field(key)).collect();
     ```
     Only scalar string keys are checked. If a dataset manifest declares files using standard TOML array format `files = ["grid_data.json"]` or `file = "grid_data.json"`, no files are parsed into `restricted`.
  3. In `xtask/policy/repository.toml`, `data_extensions` omits common power grid and market exchange formats: `.json`, `.xml`, `.mat` (MATPOWER / MATLAB), and `.cdf` (Common Data Format).
  Consequently, committing a restricted research-only MATPOWER `.mat` file or JSON API dump outside `raw/` produces zero findings from `cargo xtask provenance`.
- **Minimal Test Inputs:**
  - Input 1: Text file containing standard OpenAI API key `sk-abcdef1234567890abcdef1234567890abcdef12345678`
  - Input 2: `manifest.toml` declaring `licence_status = "research-only"` with `files = ["restricted_grid.json"]`
- **Command Run:**
  ```bash
  cargo test -p xtask test_gap_openai_standard_key test_gap_manifest_files_array -- --nocapture
  ```
- **Observed Output:**
  ```text
  GAP 9a (OpenAI standard key): findings=[]
  GAP 9b (Manifest files array): restricted=[], findings=[]
  ```
  Both inputs produced zero findings.
- **Suggested Fix:**  
  1. Add a secret detection rule for standard `sk-` keys with minimum tail length of 48.
  2. Parse array-valued `files` as well as singular `file`/`path` in `manifest_datasets()`.
  3. Add `.mat`, `.cdf`, `.json`, and `.xml` to `data_extensions` in `xtask/policy/repository.toml`.

The transition from Python scripts to a Rust `cargo xtask` suite in PR #23 represents a major architectural upgrade that successfully addresses the 18 initial findings of ADV23-01..18.

However, because critical false negatives remain—most notably the omission of `.cargo/config` from lint checks, provider separation evasion in review gates, and attribution evasion via mathematical symbols and emojis—**PR #23 requires remediation of ADV23R-01 through ADV23R-09 before merge**.
