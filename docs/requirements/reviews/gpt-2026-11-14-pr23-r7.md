### 1. R7-01 — High — STRUCTURAL: allowlisted library names resolve to untrusted linker scripts

**Locations:** `xtask/src/build_gate.rs:747` (`LinkPolicy::library`), `:808`
(`scan`, library/search-path handling), `:1019` (`analyse`, shallow search-directory
inspection); `xtask/policy/gates.toml` (`iconv` in `link_libraries`).
**Reviewer probe:** `shadow-system-library` and direct-name/system-library controls.

Use this adapter source:

```rust
#![allow(unsafe_code)]
#[link(name = "iconv")]
unsafe extern "C" { fn reviewer_native_value() -> i32; }
/// ```
/// assert_eq!(egs_solver_highs::value(), 23);
/// ```
pub fn value() -> i32 { unsafe { reviewer_native_value() } }
```

Use this build.rs:

```rust
#![forbid(unsafe_code)]
use std::{path::PathBuf, process::Command};
fn main() {
 let out = PathBuf::from(std::env::var_os("OUT_DIR").unwrap());
 let hidden = out.join("hidden");
 std::fs::create_dir_all(&hidden).unwrap();
 let src = hidden.join("probe.c");
 let obj = hidden.join("probe.o");
 let lib = hidden.join("libpython3.12.a");
 std::fs::write(&src, "int reviewer_native_value(void) { return 23; }\n").unwrap();
 assert!(Command::new("cc").args(["-c", "-fPIC"]).arg(&src).arg("-o").arg(&obj).status().unwrap().success());
 assert!(Command::new("ar").arg("crs").arg(&lib).arg(&obj).status().unwrap().success());
 std::fs::write(out.join("libiconv.so"), format!("INPUT ( {} )\n", lib.display())).unwrap();
 println!("cargo:rustc-link-search=native={}", out.display());
}
```

The build gate reports **PASS**, exit 0, in all configured modes. The doctest calls
`value()` and returns the synthetic archive's value. A separate invocation of
`cargo test --doc` with the same wrapper/configuration and linker guard also passes
one actual doctest. Source and manifest policy categories pass.

The guard accepts `-liconv` because the name is allowlisted, but `-L<OUT_DIR>`
resolves it to the build script's `libiconv.so`. The real linker interprets that
file as a script and follows its `INPUT` into `hidden/libpython3.12.a`. The guard
never sees that archive path. Cargo's JSON has only the search directory; the
shallow directory scan sees `libiconv.so` and a subdirectory, so neither channel
reports NFR-10. No response file, custom `-T` flag, wrapper/configuration change,
or write outside `OUT_DIR` is involved. This is ordinary build-script output,
not the artifact-directory tampering acknowledged in ADR risks 5 and 9.

**Controls:** changing only the Rust link name to `python3.12` yields an NFR-10
finding before the real linker runs. A clean `m` system-library request without
custom native output passes. Thus the result is a library-resolution gap rather
than an unused gate or a failed build being mistaken for success.

**Suggested change:** bind allowlisted system names to trusted resolved files,
rather than trusting names while accepting arbitrary search paths. Reject a
PR/build-script search directory that shadows an allowlisted name, or resolve and
validate the selected input and any linker-script dependencies against trusted
roots. Cover dynamic and static aliases, framework search paths, and ordinary
system linker scripts with controls. Add this real Cargo fixture, including the
successful doctest, as a regression. Merely forbidding explicit script options
or scanning one more directory level does not establish the allowlist invariant.

**Locations:** `xtask/src/build_gate.rs:1156` (`feature_sets`), `:1336`

**Reviewer probe:** `dev-feature-unification`, wrapped production-build control,

**PASS**, exit 0, including its purported single-`a` build and the doctest runs.
Every `build --all-targets` run brings in the self dev-dependency, which enables
`b` and removes this native-link item. The doctest command also uses dev-dependency
feature resolution. Requesting `--no-default-features --features a` does not mean
that Cargo's resolved graph has only `a` enabled.

**Control:** reuse the gate's generated configuration and wrapper to build the
same package in production mode, omitting `--all-targets`:

```bash
RUSTC_WRAPPER="$reviewed_xtask" \
XTASK_BUILD_GATE_CONFIG="$scratch_target/egs-build-gate/config.json" \
cargo build --locked --manifest-path "$fixture/Cargo.toml" \
  --target-dir "$scratch_target" --jobs 2 \
  --package egs-solver-highs --no-default-features --features a
```

This exits 101 with the guard's explicit NFR-10 refusal of `python3.12` during
the cdylib link. Removing only `[dev-dependencies]` and its self-dependency, then
regenerating Cargo.lock offline, makes the ordinary build-gate command reject
the same source with NFR-10 (exit 1). No installed Python library is needed.

This is one selected non-default feature, not the two-or-more-feature combination
that ADR risk 8 excludes. Consequently the documented bound does not describe the
actual coverage, and R6-03's original regression does not establish the broader
single-feature claim under Cargo's resolver.

**Suggested change:** run guarded production `cargo build` configurations without
dev targets as well as the all-targets/test configurations. Define coverage in
terms of Cargo's resolved feature graph, including workspace/dependency feature
unification; either build the promised production configurations or reject an
unsupported configuration explicitly. Add this fixture and the production-build
control as a regression, and correct the ADR's coverage statement accordingly.

## Enforcement and M0 limitation assessment

The exact adapter package/directory list and its protected policy location close
the arbitrary-adapter exemption. Compiler `forbid` and root checking provide
complementary controls over ordinary local code, including macros and includes.
Registry dependencies deliberately retain their own unsafe policy; this is a
boundary around repository code, not a claim that the dependency closure contains
no unsafe Rust. Adapter build scripts remain subject to the static root forbid.
The new doctest attribute closes the previous false claim about inheritance.

The last-step/no-id/no-job-outputs checks match the submitted `policy` job, and
the gate strips the five file-command variables before starting Cargo. This is
useful containment of ordinary environment propagation. It does not make the
shell lint a complete shell-language analysis or isolate same-user build-time
code. The ADR correctly acknowledges action post-steps and build scripts/proc
macros sharing the job's user. Acceptable for M0's unprivileged hosted policy
job, with exact-head review; executable isolation evidence on the D-65 runner
remains the M1 condition in NFR-12.

The provenance gate now rejects the reported case variants and checks registered
research-only names independently of extension. It enforces the declared manifest,
file-extension and sample-path policy. It cannot establish that a declaration is
truthful, identify every dataset hidden in an arbitrary source/text file, or make
an unsupported licence commercially valid; source/licence review still supplies
that evidence. No additional concrete provenance regression was found here.

ADR residual risks 1–5 (bootstrap/branch-protection/account trust and same-user
tampering), corrected host-target risk 6, and static-bundling risk 7 remain material
review obligations. The explicit bound on multi-feature-only code in risk 8 and
fail-closed long response files in risk 10 are reasonable M0 limits when stated
as bounds rather than universal enforcement. Risk 9 accurately acknowledges that
artifact-location trust is not proof of who wrote a file. However, it does not
cover R7-01: that input writes only inside OUT_DIR, using normal link-search
output. Risk 8 also does not cover R7-02's single-feature production build. Those
two limitations must be corrected in both enforcement and documentation; the
existing addendum cannot justify accepting these false negatives.

Attribution's common Rust/Perl definitions and the fourteen fixed round-6 inputs
are a substantial improvement, with human/prose controls and hook parity. They
remain a finite lexical policy, backed by review, rather than recognition of all
possible natural-language credit. R7-03 is a concrete current omission, including
an integration already adding credit to this repository's PR body.
