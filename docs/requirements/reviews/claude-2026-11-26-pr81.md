## Assessment

**How the merge result is classified.** Both gates now compare current main with the real `merge-tree --write-tree` result:
- `independent_review` and `policy_approval` both diff main against that tree.
- `still_current` checks each path against `main` versus the merged tree.
- Path listing uses `--no-renames`, so a renamed report can't hide a deletion.
- The workflow scan in `policy_approval` reads the merged tree, not the head.
- A merge result equal to main returns early with no findings, so a no-op PR passes and the merge changes nothing.
- Main-only changes never appear as PR changes.

**Conflicts and criss-cross histories.**
- When `merge-tree` hits a conflict it exits non-zero. The `git` helper turns that into `Err`, so both gates fail closed (`pr75_conflicting_merges_fail_both_gates_closed`).
- A criss-cross history with two merge bases is merged recursively. That matches how Git itself merges.
- An "ours"-style revert hidden behind a criss-cross shows up as a change in the merge result, and both gates reject it. The tests `pr75_criss_cross_reverts_require_both_gates`, `pr75_criss_cross_noop_preserves_main` and `pr75_single_base_revert_requires_both_gates` cover this.
- Today #81 itself has a single merge base, so none of this affects it.

**Duplicate or malformed headers.**
