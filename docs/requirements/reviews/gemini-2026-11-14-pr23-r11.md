### ADV23R11-01: UTF-8 Byte-Order Mark (BOM) in Extensionless Scripts Bypasses `shebang_interpreter` and Python/Julia Policy (D-73)

- **Classification:** CORE
- **Severity:** HIGH
- **Area:** Scripting Language Policy (D-20, D-73, NFR-10)
- **File & Line Citation:** [xtask/src/repository.rs:63-137](../../../xtask/src/repository.rs#L63-L137)
- **Description:**  
  Decision D-20 and D-73 prohibit Python, Julia, and other scripting languages outside `spikes/` and allow-listed reference validators.  
  In `xtask/src/repository.rs`, `shebang_interpreter` extracts the interpreter from the first line of a script:
  ```rust
  pub fn shebang_interpreter(first: &str) -> Option<String> {
      let rest = first.strip_prefix("#!")?;
      ...
  ```
  In Unix and cross-platform environments, scripts frequently omit file extensions (e.g., `crates/run_tool`, `ci/helper`, `tools/dispatch`). Many text editors (such as VS Code, Notepad, or Windows tools) save UTF-8 files with a Byte-Order Mark (`\xEF\xBB\xBF` / `\u{feff}`).  
  When an extensionless script begins with a UTF-8 BOM followed by a shebang (`\xef\xbb\xbf#!/usr/bin/env python3` or `\xef\xbb\xbf#!/usr/bin/env julia`):
  1. The first line decoded starts with `\u{feff}#!`.
  2. `first.strip_prefix("#!")` returns `None`.
  3. `shebang_interpreter` returns `None`.
  4. Because the file has no extension, `LANGUAGE_EXTENSIONS` does not match.
  5. `cargo xtask policy` reports `PASS: python` with exit code 0.
- **Minimal Test Inputs:**
  - Tracked extensionless file `crates/run_tool` containing `\xef\xbb\xbf#!/usr/bin/env python3\nprint("hello")\n`
  - Tracked extensionless file `crates/run_julia` containing `\xef\xbb\xbf#!/usr/bin/env julia\nprintln("hello")\n`
- **Commands Run:**
  ```bash
  printf '\xef\xbb\xbf#!/usr/bin/env python3\nprint("hello")\n' > crates/run_tool
  git add -f crates/run_tool
  cargo xtask policy
  ```
- **Observed Output:**
  ```text
  PASS: unsafe-scope
  PASS: manifests
  PASS: workflows
  PASS: python
  PASS: codeowners
  ```
  Clean pass with exit code 0.
- **Suggested Fix:**  
  In `shebang_interpreter`, strip any leading UTF-8 BOM (`\u{feff}`) before inspecting `#!"`:
  ```rust
  let trimmed = first.trim_start_matches('\u{feff}');
  let rest = trimmed.strip_prefix("#!")?;
  ```

### ADV23R11-02: Provenance Gate (D-56) Omits Standard Infeasibility (`.iis`), State (`.svf`), SAT (`.cnf`), SMT (`.smt2`), and AMPL (`.run`) Optimization Files

- **Classification:** CORE
- **Severity:** HIGH
- **Area:** Provenance Gate & Dataset Formats (D-56, ADR 0001)
- **File & Line Citation:** [xtask/policy/repository.toml:60-70](../../../xtask/policy/repository.toml#L60-L70), [xtask/src/repository.rs:762-789](../../../xtask/src/repository.rs#L762-L789)
- **Description:**  
  Decision D-56 prohibits committing datasets outside allow-listed open-commercial sample paths (`spikes/data/samples/*`).  
  The repository develops mathematical optimization engines and solver adapters (`egs-solver-highs`, `egs-solver-gurobi`, `egs-solver-xpress`, `egs-solver-cuopt`).  
  In mathematical programming, power grid dispatch simulation, constraint programming, and operations research:
  - `.iis`: Irreducible Inconsistent Subsystems files are the industry-standard infeasibility conflict models output by CPLEX, SCIP, and other solvers (analogous to Gurobi's `.ilp`, which was added in revision 11).
  - `.svf`: FICO Xpress saved problem state files produced by the `SAVESTATE` command in Xpress.
  - `.cnf`: DIMACS CNF files are the universal problem benchmark format for Boolean satisfiability (SAT) solvers. While pseudo-Boolean formats (`.opb`, `.wbo`, `.pbo`) were added in revision 11, `.cnf` was omitted.
  - `.smt2` / `.smt`: SMT-LIB standard format for Satisfiability Modulo Theories solver instances.
  - `.run`: AMPL solver execution and solve scripts used alongside AMPL `.mod` and `.dat` formulations.  
  
  None of `.iis`, `.svf`, `.cnf`, `.smt2`, or `.run` is listed in `data_extensions` in `xtask/policy/repository.toml`, and none is detected by `data_signature`. When any of these unapproved datasets or solver state files is committed in `spikes/`, the gate reports clean pass with exit code 0.
- **Minimal Test Inputs:**
  - `spikes/conflict.iis`
  - `spikes/model.svf`
  - `spikes/problem.cnf`
  - `spikes/problem.smt2`
  - `crates/solve.run`
- **Commands Run:**
  ```bash
  echo "CONFLICT" > spikes/conflict.iis
  echo "SAVESTATE" > spikes/model.svf
  echo "p cnf 3 2" > spikes/problem.cnf
  echo "(assert true)" > spikes/problem.smt2
  echo "solve; display x;" > crates/solve.run
  git add -f spikes/conflict.iis spikes/model.svf spikes/problem.cnf spikes/problem.smt2 crates/solve.run
  cargo xtask provenance
  cargo xtask policy
  ```
- **Observed Output:**
  ```text
  PASS: provenance/secrets/data (D-56)
  PASS: python
  ```
  All commands passed with exit code 0.
- **Suggested Fix:**  
  Add `.iis`, `.svf`, `.cnf`, `.smt2`, `.smt`, and `.run` to `data_extensions` in `xtask/policy/repository.toml`, and add `.run` to `LANGUAGE_EXTENSIONS` in `xtask/src/repository.rs`.

### ADV23R11-03: Standalone Autonomous Coding Assistants `Blackbox` and `Sweep` Evade Pattern 55 Sentence-Level Attribution Footers

- **Classification:** PERIPHERAL
- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Tool Dictionaries
- **File & Line Citation:** [.githooks/attribution-patterns.regex:24, 47, 49, 55](../../../.githooks/attribution-patterns.regex#L24-L55)
- **Description:**  
  Decision D-52 prohibits whole-line AI attribution trailers and footers in commits, PR titles, and PR bodies.  
  In revision 11 (commit `acc98b4`), bare `Blackbox` and `Sweep` were added as `TOOLNAME` solely within git trailer patterns:
  ```regex
  define TOOLNAME = (?:(?:blackbox|sweep)(?:{{SEP}}+(?:{{QUALIFIER}}|{{VERSION}})(?![\p{L}\p{N}]))*{{SEP}}*)
  ```
  However, in sentence-level footers (Pattern 55):
  ```regex
  ^\s*{{DECOR}}(?:\*{1,2})?{{ATTRIBUTE}}\s+{{BY}}\s*:?\s*{{HELP}}?(?:{{NAME}}|\[{{NAME}}\]\(https?://[^\s)]+\))[.!]?(?:\*{1,2})?\s*$
  ```
  Pattern 55 matches `{{NAME}}` which expands via `{{AINAME}}` to `{{MODEL}}`.  
  In `MODEL` (line 24), `blackbox` and `sweep` still strictly require `[\s_-]*ai`:
  ```regex
  blackbox[\s_-]*ai(?![\p{L}\p{N}])|sweep[\s_-]*ai(?![\p{L}\p{N}])
  ```
  As a result, sentence footers attributing code generation, writing, or assistance to these tools by their product name:
  - `Generated by Blackbox`
  - `Written by Blackbox`
  - `Assisted by Blackbox`
  - `Generated by Sweep`
  - `Written by Sweep`
  - `Assisted by Sweep`  
  fail to match `MODEL` and pass completely undetected. Notably, `Generated by Blackbox` and `Generated by Sweep` were explicit reproduction test inputs in ADV23R10-04.
- **Minimal Test Inputs:**
  - Input 1: `Generated by Blackbox`
  - Input 2: `Generated by Sweep`
  - Input 3: `Written by Blackbox`
  - Input 4: `Assisted by Sweep`
- **Commands Run:**
  ```bash
  cargo xtask attribution --base HEAD --head HEAD --title "Generated by Blackbox"
  cargo xtask attribution --base HEAD --head HEAD --title "Generated by Sweep"
  cargo xtask attribution --base HEAD --head HEAD --title "Written by Blackbox"
  cargo xtask attribution --base HEAD --head HEAD --title "Assisted by Sweep"
  ```
- **Observed Output:**
  ```text
  scanned 0 commit(s), 0 added line(s), title=yes, body=no
  PASS: attribution policy (D-52)
  ```
  All 4 inputs passed with exit code 0.
- **Suggested Fix:**  
  Include `{{TOOLNAME}}` in `NAME` or allow `ai` to be optional in `MODEL`:
  `blackbox(?:[\s_-]*ai)?(?![\p{L}\p{N}])|sweep(?:[\s_-]*ai)?(?![\p{L}\p{N}])`.

### ADV23R11-04: Prepositional Gratitude Footers `Thanks to <Model>` and `Courtesy of <Model>` Evade Attribution Patterns

- **Classification:** PERIPHERAL
- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Prepositional Credit Phrases
- **File & Line Citation:** [.githooks/attribution-patterns.regex:42-57](../../../.githooks/attribution-patterns.regex#L42-L57)
- **Description:**  
  In `.githooks/attribution-patterns.regex`, `BY` includes gratitude prepositional phrases:
  ```regex
  define BY = (?:...|thanks\s+to|courtesy\s+of|...)
  ```
  In revision 11 (commit `acc98b4`), Pattern 57 was added to catch credit phrases without a leading verb:
  ```regex
  ^\s*{{DECOR}}(?:\*{1,2})?{{BY}}\s+{{HELP}}(?:{{NAME}}|\[{{NAME}}\]\(https?://[^\s)]+\))[.!]?(?:\*{1,2})?\s*$
  ```
  Notice that Pattern 57 strictly requires `{{HELP}}` (assistance nouns such as `help`, `assistance`, `guidance`, `input`, etc.) immediately following `{{BY}}`.  
  In software development PR descriptions and commit messages, authors often express standalone gratitude directly to an AI model:
  - `Thanks to Claude`
  - `Courtesy of Claude`
  - `Special thanks to Claude`
  - `Thanks to ChatGPT`
  - `Courtesy of GPT-4`  
  Because these phrases do not contain an assistance noun (`HELP`), Pattern 57 fails to match. Because they lack an initial action verb (`ATTRIBUTE`), Pattern 55 fails to match. Because they lack git trailer syntax (`:` separator), Patterns 49 and 53 fail to match. Consequently, all such gratitude footers pass undetected.
- **Minimal Test Inputs:**
  - Input 1: `Thanks to Claude`
  - Input 2: `Courtesy of Claude`
  - Input 3: `Special thanks to Claude`
  - Input 4: `Thanks to ChatGPT`
- **Commands Run:**
  ```bash
  cargo xtask attribution --base HEAD --head HEAD --title "Thanks to Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Courtesy of Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Special thanks to Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Thanks to ChatGPT"
  ```
- **Observed Output:**
  ```text
  scanned 0 commit(s), 0 added line(s), title=yes, body=no
  PASS: attribution policy (D-52)
  ```
  All 4 inputs passed with exit code 0.
- **Suggested Fix:**  
  Make `{{HELP}}` optional in Pattern 57 when `{{BY}}` is `thanks to` or `courtesy of`:
  `^\s*{{DECOR}}(?:\*{1,2})?(?:{{BY}}\s+{{HELP}}|(?:special\s+)?thanks\s+to\s+|courtesy\s+of\s+)(?:{{NAME}}|\[{{NAME}}\]\(https?://[^\s)]+\))[.!]?(?:\*{1,2})?\s*$`.

### ADV23R11-05: Attribution Clauses and Trailers Using `Credit`, `Credited`, and `Credits` Omitted from Detection Patterns

- **Classification:** PERIPHERAL
- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Collaboration Verb Coverage
- **File & Line Citation:** [.githooks/attribution-patterns.regex:41, 49, 53, 55](../../../.githooks/attribution-patterns.regex#L41-L55)
- **Description:**  
  In `.githooks/attribution-patterns.regex:41`, `ATTRIBUTE` enumerates action and collaboration verbs recognized in attribution footers.  
  It omits standard attribution credit terms:
  - `credit`
  - `credited`
  - `credits`
  - `co-credit` / `co-credited`  
  When an author writes attribution phrases or trailers such as:
  - `Credited to Claude`
  - `Credit: Claude`
  - `Credits: Claude`
  - `Co-credit: Claude`

  2. `credit` is not recognized as a trailer verb prefix in Pattern 49, so Pattern 49 fails.
  3. `credit` is not in `HELP`, so Pattern 57 fails.
  4. The check reports clean pass with exit code 0.
- **Minimal Test Inputs:**
  - Input 1: `Credited to Claude`
  - Input 2: `Credit: Claude`
  - Input 3: `Credits: Claude`
  - Input 4: `Co-credit: Claude`
- **Commands Run:**
  ```bash
  cargo xtask attribution --base HEAD --head HEAD --title "Credited to Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Credit: Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Credits: Claude"
  cargo xtask attribution --base HEAD --head HEAD --title "Co-credit: Claude"
  ```

- **Observed Output:**
  ```text
  scanned 0 commit(s), 0 added line(s), title=yes, body=no
  ```

  Add `credit(?:ed|s)?` and `co[{{DASH}}\s]*credit(?:ed)?` to `ATTRIBUTE`, and add `credited\s+to` to trailer and footer patterns.

## 5. Conclusion & Recommendations

The revision 11 updates on PR #23 head `d71cf40d1fdae6eb62de28c366ce925ec3108579` successfully remediate all round 10 items except ADV23R10-04, which was only partially addressed (bare `Blackbox` and `Sweep` were added to git trailer regex, but continue to evade sentence-level attribution footers).

This round 11 adversarial robustness review confirms 6 remaining false negatives:
- **2 CORE gaps:** omission of leading UTF-8 BOM handling in `shebang_interpreter` allowing extensionless Python and Julia scripts outside `spikes/` to pass undetected (ADV23R11-01); and omission of CPLEX/SCIP infeasibility (`.iis`), FICO Xpress state (`.svf`), DIMACS SAT (`.cnf`), SMT-LIB2 (`.smt2`), and AMPL (`.run`) optimization files from `data_extensions` and language policy (ADV23R11-02).
- **4 PERIPHERAL gaps:** evasion of Pattern 55 by bare `Blackbox` and `Sweep` without ` AI` suffix (ADV23R11-03); evasion of verbless Pattern 57 by standalone gratitude footers `Thanks to <Model>` and `Courtesy of <Model>` (ADV23R11-04); omission of credit verbs and trailers (`Credit:`, `Credited to`, `Credits:`) from `ATTRIBUTE` (ADV23R11-05); and omission of major code generation models `CodeGeeX` and `Granite` from `MODEL` (ADV23R11-06).

PR #23 requires remediation of these 6 items prior to milestone M0 closure.
