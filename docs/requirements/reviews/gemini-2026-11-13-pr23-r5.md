   - Verified that `pull_request_target` triggers execute strictly from `main` (`refs/remotes/origin/main`).
   - The pull request head is fetched strictly as data objects into `refs/remotes/pull/head`. PR code is never checked out, compiled, or executed by `trusted-gates.yml`.

   - Verified Git wildmatch compatibility. Partial `**` runs that do not fill a whole component (e.g. `a**/b`, `x/**y`) are rejected as unsupported syntax under `partial_globstar()`.

### ADV23R5-01: `RUSTC_WORKSPACE_WRAPPER` and `CARGO_BUILD_RUSTC_WRAPPER` Bypass Workflow Environment Variable Check

- **Classification:** STRUCTURAL
- **Severity:** HIGH
- **Area:** CI Workflow Checks / Compiler Flag Hardening (NFR-12, D-73)
- **File & Line Citation:** [xtask/src/workflows.rs:360-370](../../../xtask/src/workflows.rs#L360-L370)
- **Description:**  
  Decision NFR-12 and `xtask/src/workflows.rs` prohibit setting compiler flags, wrappers, or linkers in workflow `env:` tables to ensure lint levels (such as `forbid(unsafe_code)`) cannot be overridden.  
  In `xtask/src/workflows.rs`, `check_env()` inspects environment variable names:
  ```rust
  fn check_env(path: &str, name: &str, value: &Yaml, findings: &mut Vec<Finding>) {
      let text = scalar(value).to_ascii_lowercase();
      if (name.contains("RUSTFLAGS") || name.contains("RUSTDOCFLAGS") || name == "RUSTC_WRAPPER")
          && !text.is_empty()
      {
          findings.push(Finding::at(
              path,
              None,
              format!("`{name}` may not be set in workflows (lint levels stay in Cargo.toml)"),
          ));
      }
  }
  ```
  Cargo documents and executes wrapper programs specified by several environment variables:
  - `RUSTC_WORKSPACE_WRAPPER`: invokes a wrapper for all workspace member compilation units.
  - `CARGO_BUILD_RUSTC_WRAPPER`: Cargo config/env equivalent of `build.rustc-wrapper`.
  - `CARGO_BUILD_RUSTC_WORKSPACE_WRAPPER`: Cargo config/env equivalent of `build.rustc-workspace-wrapper`.
  
  Because `check_env()` tests exact string equality `name == "RUSTC_WRAPPER"`, setting `RUSTC_WORKSPACE_WRAPPER` or `CARGO_BUILD_RUSTC_WRAPPER` evaluates to `false` for all three conditions. An untrusted pull request can define `env: { RUSTC_WORKSPACE_WRAPPER: "/path/to/script" }` in `.github/workflows/ci.yml`. When `cargo clippy` or `cargo nextest` executes, Cargo invokes the wrapper with arguments `[wrapper, rustc, ...]`, allowing the script to append `-A unsafe_code`, inject arbitrary compilation flags, or execute malicious commands during build steps, completely bypassing the CI policy check.
- **Minimal Test Input:**
  Tracked `.github/workflows/ci.yml`:
  ```yaml
  name: ci
  on:
    pull_request:
      types: [opened]
  permissions:
    contents: read
  env:
    RUSTC_WORKSPACE_WRAPPER: "/usr/local/bin/wrapper"
  jobs:
    rust-linux:
      runs-on: ubuntu-24.04
      steps:
        - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1
          with: {persist-credentials: false}
        - run: echo 1
  ```
- **Command Run:**
  ```bash
  cargo xtask policy
  ```
- **Observed Output:**
  ```text
  PASS: unsafe-scope and native-runtimes
  PASS: manifests
  PASS: workflows
  PASS: python
  PASS: codeowners
  ```
  The check passed with exit code 0.
- **Suggested Fix:**  
  In `xtask/src/workflows.rs:check_env()`, update the check to test for any wrapper variable:
  ```rust
  if (name.contains("RUSTFLAGS") || name.contains("RUSTDOCFLAGS") || name.contains("RUSTC_WRAPPER") || name.contains("RUSTC_WORKSPACE_WRAPPER")) && !text.is_empty()
  ```

### ADV23R5-02: `OUT_DIR` Substring in `include!(concat!(...))` Suppresses Unreachable Include Detection and Skips Uninspected Files

- **Classification:** STRUCTURAL
- **Severity:** HIGH
- **Area:** Rust Policy / Module Reachability & Unsafe Scope (ADR 0001, NFR-10)
- **File & Line Citation:** [xtask/src/rust_policy.rs:727-735, 890-915](../../../xtask/src/rust_policy.rs#L727-L735)
- **Description:**  
  In `xtask/src/rust_policy.rs`, `Modules::include()` resolves included files for policy inspection:
  ```rust
  fn include(&mut self, tokens: TokenStream, line: usize) {
      if let Ok(path) = syn::parse2::<syn::LitStr>(tokens.clone()) {
          match join_dir(self.file_dir, &path.value()) {
              Some(candidate) if self.files.contains(&candidate) => {
                  self.found.push((candidate, true));
              }
              _ => self.unresolved.push((line, path.value())),
          }
      } else if !tokens.to_string().contains("OUT_DIR") {
          // Generated code under OUT_DIR is produced by the (scanned) build
          // script; any other computed path cannot be followed.
          self.unresolved.push((line, tokens.to_string()));
      }
  }
  ```
  When the argument to `include!` is a non-literal expression (such as `concat!(...)`), `syn::parse2::<syn::LitStr>` fails. `include()` then inspects `tokens.to_string().contains("OUT_DIR")`. If the token stream contains `"OUT_DIR"`, it silently suppresses reporting the expression as unresolved.  
  Crucially, it does NOT add the file to `self.found`. In `check_sources()`, files to be scanned are gathered from:
  1. All tracked `.rs` files where `in_scope(path)` is true (`!path.starts_with("spikes/")`).
  2. All files reachable in `reached`.
  
  If a production source file includes a file via `include!(concat!("spikes/native.inc", env!("OUT_DIR")));` (or `include!(concat!(env!("OUT_DIR"), "/../spikes/native.inc"));`):
  1. The inclusion contains `"OUT_DIR"`, so `self.unresolved` is not triggered.
  2. The file is not added to `self.found`, so it is not in `reached`.
  3. The file is under `spikes/` and does not end in `.rs`, so `in_scope()` and `.ends_with(".rs")` exclude it from `scanned`.
  
  Rustc compiles the included file as part of the production crate. The included file can link forbidden native runtimes (`#[link(name = "python3.12")]`) or lower `unsafe_code`, and `cargo xtask policy` gives a clean pass.
- **Minimal Test Input:**
  In `crates/engine/src/lib.rs`:
  ```rust
  #![forbid(unsafe_code)]
  include!(concat!("spikes/native.inc", "" /* not comment */, env!("OUT_DIR")));
  ```
  In `spikes/native.inc`:
  ```rust
  #[link(name = "python3.12")]
  unsafe extern "C" {}
  ```
- **Command Run:**
  ```bash
  cargo xtask policy
  ```
- **Observed Output:**
  ```text
  PASS: unsafe-scope and native-runtimes
  PASS: manifests
  PASS: workflows
  PASS: python
  PASS: codeowners
  ```
  The check passed with exit code 0.
- **Suggested Fix:**  
  Parse literal concatenations (`concat!(...)`) to resolve their static prefix/path when possible, and ensure non-literal include expressions fail closed by being flagged as unresolved rather than suppressed by substring matching on `"OUT_DIR"`.

### ADV23R5-03: Macro-Generated `#[path = "..."] mod name;` Declarations Omit Path Attributes and Fail to Resolve Custom Module Files

- **Classification:** STRUCTURAL
- **Severity:** HIGH
- **Area:** Rust Policy / Module Reachability (ADR 0001, NFR-10)
- **File & Line Citation:** [xtask/src/rust_policy.rs:688-698](../../../xtask/src/rust_policy.rs#L688-L698)
- **Description:**  
  In `xtask/src/rust_policy.rs`, `Modules::scan_tokens()` scans macro bodies for module declarations:
  ```rust
  TokenTree::Ident(ident) if ident.unraw() == "mod" => {
      if let (Some(TokenTree::Ident(name)), Some(TokenTree::Punct(semi))) =
          (trees.get(index + 1), trees.get(index + 2))
          && semi.as_char() == ';'
      {
          self.declare(&name.unraw().to_string(), &[], line);
      }
  }
  ```
  Notice that `self.declare()` is invoked with `&[]` (an empty slice of path attributes).

When Rustc compiles the crate, it follows the `#[path = "native.inc"]` attribute and compiles `native.inc`. `native.inc` is never reached or scanned by `xtask`, allowing forbidden native links (`#[link(name = "python3.12")]`) to compile undetected.
- **Minimal Test Input:**

  ```rust
  #![forbid(unsafe_code)]
  macro_rules! decl {
      () => {
          #[path = "native.inc"]
          mod native;
      };
  }
  decl!();
  ```
  In `crates/engine/src/native.rs` (benign dummy file):
  ```rust
  // clean
  ```
  In `crates/engine/src/native.inc` (actual module compiled by rustc):
  ```rust

  unsafe extern "C" {}
  ```
- **Command Run:**

- **Observed Output:**

  ```text
  PASS: manifests
  PASS: workflows
  PASS: python
  PASS: codeowners
  ```
  The check passed with exit code 0.
- **Suggested Fix:**  
  In `scan_tokens()`, inspect preceding attribute tokens for `#[path = "..."]` on the macro-generated module declaration and pass the resolved path to `declare()`.

### ADV23R5-04: Macro Substitution in `#[link(name = $lib)]` Attributes Bypasses Native Runtime Linking Detection (NFR-10)

- **Classification:** STRUCTURAL
- **Severity:** HIGH
- **Area:** Rust Policy / Native Runtime Linking (NFR-10)
- **File & Line Citation:** [xtask/src/rust_policy.rs:59-75, 183-195](../../../xtask/src/rust_policy.rs#L59-L75)
- **Description:**  
  Decision NFR-10 forbids linking native Python or Julia runtimes.  
  In `xtask/src/rust_policy.rs`, `links_runtime()` scans token streams for `link(...)` ident groups:
  ```rust
  pub fn links_runtime(tokens: TokenStream) -> bool {
      let trees: Vec<TokenTree> = tokens.into_iter().collect();
      for (index, tree) in trees.iter().enumerate() {
          match tree {
              TokenTree::Ident(ident) => {
                  if ident.unraw() == "link"
                      && let Some(TokenTree::Group(group)) = trees.get(index + 1)
                      && group.delimiter() == Delimiter::Parenthesis
                      && names_runtime(&decoded_text(group.stream()))
                  {
                      return true;
                  }
              }
              TokenTree::Group(group) if links_runtime(group.stream()) => return true,
              _ => {}
          }
      }
      false
  }
  ```
  When a macro generates an FFI link attribute using a metavariable argument:
  ```rust
  macro_rules! link_lib {
      ($lib:expr) => {
          #[link(name = $lib)]
          unsafe extern "C" {}
      };
  }
  link_lib!("python3.12");
  ```
  1. In the macro definition, the token stream inside `link(...)` is `name = $ lib`. `names_runtime()` evaluates to `false` because `$lib` is not a runtime name.
  2. At the macro invocation site `link_lib!("python3.12");`, `visit_macro()` passes `mac.tokens` (`"python3.12"`) to `links_runtime()`. Because the invocation tokens contain only `"python3.12"` without an ident `link` followed by a parenthesis group, `links_runtime()` evaluates to `false`.
  
  Because `syn::visit` operates on the unexpanded AST, the link attribute formed across the macro expansion boundary is never evaluated as a unit, and `cargo xtask policy` gives a clean pass.
- **Minimal Test Input:**
  In `crates/solver-highs/src/lib.rs`:
  ```rust
  macro_rules! link_lib {
      ($lib:expr) => {
          #[link(name = $lib)]
          unsafe extern "C" {}
      };
  }
  link_lib!("python3.12");
  ```
- **Command Run:**
  ```bash
  cargo xtask policy
  ```
- **Observed Output:**
  ```text
  PASS: unsafe-scope and native-runtimes
  PASS: manifests
  PASS: workflows
  PASS: python
  PASS: codeowners
  ```
  The check passed with exit code 0.
- **Suggested Fix:**  
  When scanning macro invocations in `visit_macro()`, check if arguments to macros name prohibited native runtimes (`names_runtime(&decoded_text(mac.tokens.clone()))`), or expand simple declarative macros before AST traversal.

### ADV23R5-05: Patched Dependencies in Build Context Lose `build_context` Flag

- **Description:**

  ```rust
  if let Some(outer) = document.get("patch").and_then(Item::as_table_like) {
      for (_, inner) in outer.iter() {
  ```

### ADV23R5-06: Preposition `via` and Verb `produced` in Attribution Footers Evade Pattern 2 (D-52)

- **Classification:** ATTRIBUTION-SPELLING
- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Footer Phrasing Variations
- **File & Line Citation:** [.githooks/attribution-patterns.regex:20](../../../.githooks/attribution-patterns.regex#L20)
- **Description:**  
  Pattern 2 matches attribution footers using:
  ```regex
  ^\s*{{DECOR}}(?:\*{1,2})?(?:generated|written|authored|assisted|powered|created|made|drafted|built|crafted)\s+(?:with|by|using)\s*:?[\s]*(?:the\s+help\s+of\s+)?(?:(?:{{AINAME}}|AI|LLM)|\[(?:{{AINAME}}|AI|LLM)\]\(https?://[^\s)]+\))[.!]?(?:\*{1,2})?\s*$
  ```

  Phrases commonly generated by developer tools such as `Generated via Claude Code`, `Authored via ChatGPT`, `Created via Copilot`, and `Produced by Claude` evade all regex patterns.

  ```text
  scanned 0 commit(s), 0 added line(s), title=yes, body=no
  PASS: attribution policy (D-52)
  ```
  Both inputs passed with exit code 0.
- **Suggested Fix:**

### ADV23R5-10: Space-Separated Trailer Prefixes (`Prompted by:`, `Implemented by:`) Evade Pattern 1 (D-52)

- **Classification:** ATTRIBUTION-SPELLING
- **Severity:** HIGH
- **Area:** D-52 Attribution Policy / Trailer Prefixes
- **File & Line Citation:** [.githooks/attribution-patterns.regex:19](../../../.githooks/attribution-patterns.regex#L19)
- **Description:**  
  Pattern 1 matches trailers using:
  ```regex
  ^\s*{{DECOR}}(?:[\w{{DASH}}]*[{{DASH}}]|(?:co[{{DASH}}\s]*)?(?:authored|written|assisted|generated|created|developed|helped|signed[{{DASH}}\s]*off|pair[{{DASH}}\s]*programmed)\s+)(?:by|with)\s*:
  ```
  If a hyphen is used (e.g. `Prompted-by: Claude`), `[\w{{DASH}}]*[{{DASH}}]` matches `Prompted-`.  
  However, when a space is used (`Prompted by: Claude`, `Implemented by: Claude`, `Prepared by: Claude`), the pattern falls into the second branch `(?:authored|written|assisted|generated|created|developed|helped|signed-off|pair-programmed)`.  
  Because `prompted`, `implemented`, and `prepared` are not in this list, space-separated trailers like `Prompted by: Claude` evade Pattern 1 completely.
- **Minimal Test Input:**
  ```text
  Prompted by: Claude
  ```
- **Command Run:**
  ```bash
  cargo xtask attribution --base HEAD --head HEAD --title "Prompted by: Claude"
  ```
- **Observed Output:**
  ```text
  scanned 0 commit(s), 0 added line(s), title=yes, body=no
  PASS: attribution policy (D-52)
  ```
  The check passed with exit code 0.
- **Suggested Fix:**  
  Include `prompted`, `implemented`, and `prepared` in the allowed verb list in Pattern 1, or match `[\w{{DASH}}\s]+(?:by|with)\s*:`.
