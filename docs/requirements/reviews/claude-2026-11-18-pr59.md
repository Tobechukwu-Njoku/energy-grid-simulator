## Findings

1. **[High, blocking] Questionnaire ID collision with merged PR #58.** On `main`,
   `02-questionnaire.md` already has `## P. Candidate modelling assumptions and
   deficit proxies (PR #58)` with **Q-P-01 … Q-P-08**. PR #59 adds a second
   `## P. M1 acceptance oracles and staged evidence` with **Q-P-1 … Q-P-3**. The
   pairs Q-P-1/Q-P-01, Q-P-2/Q-P-02 and Q-P-3/Q-P-03 are different questions with
   the same section and number:
   - Q-P-1 is the staged exit boundary; Q-P-01 is the post-fault rating proxy.
   - Q-P-2 is the FX policy; Q-P-02 is ROI micro-PV.
   - Q-P-3 is numeric scale and tolerance; Q-P-03 is HVDC loss formulation.

   This breaks AGENTS.md rule 2 (stable IDs). These IDs are not yet on `main`, so
   reassign them now to a new, unused section letter in both the questionnaire and
   the spec (lines 24, 87, 94, 585, 700–702 and 710, plus the anchor link), and
   update STATUS. Do not reuse section P.

2. **[High] Not rebased on, or reconciled with, merged PR #58.** The PR is based on
   `be21158`, which predates the merge of PR #58 (`1734f39`) and PR #23. GitHub
   reports `CONFLICTING`: STATUS.md and the questionnaire conflict. Beyond the merge
   conflict, the gaps should take up what #58 now records:
   - **GAP-M1-6 / AT-M1-5.** Q-P-03 proposes a three-term HVDC loss form
     (`P_standby + k1·P + k2·P²`). AT-M1-5 fixes idle-flow loss at zero
     (line 164). Add a variant with non-zero standby loss at zero transfer. It
     should prove that the schema can represent the term, that the standby loss is
     attributed to a declared endpoint, and that the term is counted exactly once
     (FR-1.AC3).
   - **GAP-M1-4 / AT-M1-2, 7 and 29.** Q-P-01 (0.88 × post-fault rating proxy) and
     #58's unit harmonisation (ohms at 132 kV → pu, `Z_base` = 174.24 Ω) are
     concrete inferred-parameter paths. Add one variant that admits a
     proxy-derived rating, labelled inferred with an `ASSUMPTION: [Q-P-01]`
     reference, and confirm it never counts as a verified rating. Add an
     ohms-to-pu case beside the %-to-pu case in AT-M1-29.
   - **GAP-M1-7.** Line 706 calls Irish SNSP and inertia floors "unverified
     narrative". #58 Candidate 2.1 cites the EirGrid/SONI 2024 Annual Renewable
     Constraint and Curtailment Report (publisher PDF reachable at review time):
     SNSP 75%, inertia floor 23,000 MW·s, and a 3 NI + 4 ROI minimum-unit rule
     enduring from 7 April 2024. Reference it as the candidate evidence for the
     real-date variant of AT-M1-25/26. It remains `research-only`, so it is
     evidence, not a fixture.
   - **GAP-M1-5.** Cite #58's candidates and proposals for embedded PV
     (Sheffield Solar PV_Live), fuel/carbon resampling (Q-P-08) and heat-rate/VOM
     defaults (Q-P-05), so the gap table does not read as "no candidate known".

3. **[Medium] Fixture placement conflicts with the merged data gate.** F-SERIES
   (line 59) allows "rights-verified bounded extracts … pin exact bytes" of real
   open-commercial sources. The merged policy allows committed data only under
   `open_commercial_data = ["spikes/data/samples/*"]` with a registered
   open-commercial record (`xtask/policy/repository.toml`, line 64), or at exact
   `data_metadata_files` paths. Test fixtures in a crate tree would fail
   `xtask provenance`. State where the real-source extracts and synthetic fixtures
   will live. Either the probes read from `spikes/data/samples/`, or adding a test
   fixture glob is an owner policy change that must happen before AT-M1-9/11/22 can
   run. AT-M1-24 should also name `xtask provenance` (range mode) as its scanner,
   so that "scan resulting package and git range" can be measured.

4. **[Medium] AT-M1-30's exact-threshold assertion is not robust in binary64.**
   AT-M1-30 requires that a residual at exactly 1.00 × tolerance passes. 0.0011 is
   not exactly representable. A residual obtained as a difference of MW values,
   `(a + 0.0011) − a`, lands on either side of the binary64 threshold depending
   on `a`. I checked this in IEEE binary64:
   - with `a` = 100, the residual is 0.00109999999999388, which passes;
   - with `a` = 50, the residual is 0.00110000000000099, which fails.

   So the "exact threshold passes" outcome depends on how the implementation and
   the oracle construct the residual. Specify one of two approaches:
   - construct the boundary residual from the same binary64 threshold value that
     the production check uses, and keep the decimal oracle for the 0.99× and
     1.01× cases; or
   - define the comparison in exact decimal or rational arithmetic.

   Without that, the case is not reproducibly measurable at its boundary.

5. **[Low] FX quote notation is ambiguous.** AT-M1-6 (line 178) says "synthetic
   GBP/EUR rates 0.80 and 0.90". In market convention, GBP/EUR means EUR per GBP.
   The ASSUMPTION at line 90 and Q-P-2 say "GBP per EUR". The expected 800/900 GBP
   is only correct under "GBP per EUR". Write "0.80 and 0.90 GBP per EUR" in the
   fixture so the reverse-quote negative variant has an unambiguous oracle.

6. **[Low] The Irish voltage set extends the requirement without an ASSUMPTION
   label.** F-NET and AT-M1-7 add NI 275/110 kV. That is factually correct: 275 kV
   is the NI transmission backbone and the North–South tie. However, D-32 and
   FR-2.AC1 enumerate Ireland as "400/220/110 kV" only. Under AGENTS.md rule 1,
   mark this as `ASSUMPTION:` and add a short questionnaire item. Do not silently
   widen the denominator, because coverage denominators gate FR-2.AC3.

7. **[Low] The calendar case is partly inconsistent with its fixture.**
   - F-TIME includes 2023, but AT-M1-10 only exercises the 2024 transitions. Add
     the 2023-03-26 and 2023-10-29 transitions, or drop 2023 from the
     DST-transition claim.
   - tzdata models `Europe/Dublin` with negative DST, so an `is_dst` flag is
     inverted relative to London. Require the fold/offset discriminator to use the
     UTC offset, not a DST flag, and add an assertion that catches the inversion.

8. **[Low] The review-evidence decisions are not cited.** AT-M1-31 tests stale or
   spoofed review evidence and adversarial triage, but it cites only
   D-17/22/28/43/65/72. Add D-53, D-54 and D-77, the decision that defines how
   review-evidence PRs pass the gate, so that the exact-SHA review checks trace
   to their decisions.

9. **[Low] The snapshot and date are stale.** Line 4 pins source snapshot
   `be21158` and the date 2026-11-15. After the rebase, update the snapshot and
   restate the STATUS entry against the current `main`. The current STATUS
   records D-1 … D-77; this branch's copy says D-75.

Findings 1–3 must be resolved before merge. Findings 4–9 are small corrections
that the author can apply in the same revision. With those changes, I expect to
approve. The test design, coverage and oracles are otherwise sound.
