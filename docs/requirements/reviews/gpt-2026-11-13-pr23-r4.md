## Findings requiring correction

### 1. R4-01 — High — STRUCTURAL: a production Cargo target inherits the spikes exemption

**Locations:** `xtask/src/rust_policy.rs:39`, `:369`, `:385`.
**Related findings:** R3-01, R3-02 / F4, F7.

Target discovery now includes arbitrary suffixes, but the scan subsequently skips
every path under `spikes/`, including an explicit production target. Scope is
decided from the target's filename rather than the package that Cargo compiles.

**Executed reproduction:** a scratch workspace contains `crates/engine`, with
workspace `unsafe_code = "deny"` and inherited workspace lints/licence. Its package
manifest has:

```toml
[package]
name = "egs-engine"
version = "0.0.0"
edition = "2024"
license.workspace = true
[lints]
workspace = true
[lib]
path = "../../spikes/engine.rs"
```

Track `spikes/engine.rs` with this complete source:

```rust
macro_rules! lowered {
    ($lint:ident) => {
        #[allow($lint)]
        pub fn value() -> i32 {
            let n = 1;
            let p = &n as *const i32;
            unsafe { *p }
        }
    };
}
lowered!(unsafe_code);
```

`rust_policy::check_sources` returns **[]**, and `check_manifests` also returns
**[]**. Real `cargo check --offline` exits **0**, compiling `egs-engine` with the
unsafe pointer dereference despite inherited deny. Prepending the required
`#![forbid(unsafe_code)]` makes the same Cargo check fail with a forbid diagnostic.
No solver adapter is involved.

**Regression gap:** the new arbitrary-suffix fixture keeps all selected files
under `crates/engine/`; it never crosses the exemption boundary.

**Suggested change:** for every production package, enforce its root and build-script
rules on every Cargo-selected input regardless of its physical directory. Either
reject production target/dependency paths into exploratory directories or include
them in the production scan. Keep ordinary standalone spikes exempt. Add this real
Cargo fixture and its forbid/compiler control; apply equivalent treatment to
explicit build scripts and other target kinds.

### 2. R4-02 — High — STRUCTURAL: `**/` can manufacture effective CODEOWNERS coverage

**Locations:** `xtask/src/util.rs:239`, `xtask/src/repository.rs:960`.
**Related finding:** R3-04 / F8.

The glob implementation removes the slash after `**`, then allows arbitrary byte
prefixes to be consumed. Git's `**/` matches directory components; it cannot consume
part of a filename and pretend a directory separator existed.

**Executed reproduction:** protect `/xtask/`, track `xtask/evillib.rs`, and supply:

```text
/xtask/ @Owner
/xtask/evillib.rs @someone
/xtask/**/lib.rs @Owner
```

`check_codeowners_paths` returns **[]**. `codeowners_match` reports that the final
rule matches `xtask/evillib.rs`. Independently place only `/xtask/**/lib.rs` in a
scratch `.gitignore`: `git check-ignore --no-index xtask/evillib.rs` exits **1**,
confirming it does not match under the underlying pattern rules. The effective
CODEOWNERS owner is therefore `@someone`, while the checker claims owner coverage.
Removing the final rule causes the checker to reject the narrower assignment,
which isolates the false override. This is not the documented final-`/*` divergence.

**Regression gap:** the 308-case Git differential test includes valid directory
`**/` matches, but no path with a filename prefix before the literal final name.

**Suggested change:** use a mature matching implementation with CODEOWNERS'
documented exceptions, or enforce path-component semantics for `**/`. Extend the
differential fixture with `xtask/evillib.rs` versus `xtask/lib.rs` and
`xtask/src/lib.rs`, then assert the effective-owner result above is rejected.

### 3. R4-03 — Medium — STRUCTURAL: nested manifest arrays silently discard restricted files

**Location:** `xtask/src/repository.rs:163` (`collect_files`).
**Related finding:** ADV23R3-06.

Collection recurses into inline tables inside arrays, but passes every other
element to a string-only closure. An inner array is silently ignored. The parser
neither traverses it nor rejects the unsupported shape.

**Executed reproduction:** track `data/manifest.toml` containing:

```toml
[[datasets]]
name = "r"
licence_status = "research-only"
files = [["restricted.txt"]]
```

Also track `data/restricted.txt` containing a synthetic fixture. Full
`repository::provenance` returns **[]**. Changing only the last line to
`files = ["restricted.txt"]` makes the same full gate report the committed
research-only file. Using `.txt` isolates manifest registration from the separate
data-extension allow-list, just as the original checksum-index finding did.

**Regression gap:** the claimed any-depth mechanism tests one array of strings,
an array of inline tables and a nested table, but no array nested in an array.

**Suggested change:** recurse uniformly over every TOML array/table value while
preserving the enclosing file-key context, or reject unsupported file-reference
shapes with a finding. Add this input to the full provenance fixture; both malformed
schema rejection and correct research-only registration are safe outcomes.

### 4. R4-04 — Medium — STRUCTURAL: filename suffix still controls whether a manifest can be ignored

**Location:** `xtask/src/repository.rs:803` (`misnamed_manifest`).
**Related finding:** ADV23R3-07.

The detector returns before checking the manifest-like name or declared licence
status unless the filename has a listed structured-data extension. An extensionless
file named `provenance` is therefore ignored even when it is valid TOML declaring
research-only records. Canonical-name enforcement is incomplete.

**Executed reproduction:** track a normal `data/manifest.toml` with one
open-commercial dataset, so the non-vacuity check is satisfied. Separately track
`data/provenance` containing:

```toml
[[datasets]]
name = "r"
licence_status = "research-only"
file = "restricted.txt"
```

Track `data/restricted.txt` with synthetic content. Full `repository::provenance`
returns **[]**. `git mv data/provenance data/provenance.toml`, without changing
contents, makes it reject the misnamed manifest.

**Regression gap:** every misnamed input in the new tests has a recognized suffix.
An unrelated valid manifest already suffices to avoid the existing non-vacuity check.

**Suggested change:** enforce the reserved manifest-like naming rule independently
of suffix, or explicitly reject extensionless manifest declarations in dataset
locations. Preserve the intentional exemption for ordinary prose/review documents.
Add the extensionless input beside a valid canonical manifest and assert the full
gate rejects it; the check must not rely on the restricted payload's extension.
