# PR #75 code review — 2026-11-18

Scope: `fix/review-evidence-loop`, including the classifier, direct evidence
validator, tests, STATUS update and D-77. The reviewed head was obtained with
`gh pr view 75 --json headRefOid`. PR #75 is not modified by this review.

## Findings

1. **[P1] Main-only changes are mistaken for changes owned by the evidence PR.**
   `xtask/src/review_gates.rs:619` calls `changed_paths(main, head)` before the
   direct evaluator. This is a two-tree diff, not the PR's merge-base-to-head
   change set. Create a branch adding `pr-report.md`, then independently merge
   `later-main-report.md` into main. The branch neither deletes nor touches the
   latter, but the evaluator reports that it "cannot be deleted" because it is
   absent from the branch's older tree. If main instead acquires a non-review
   file, the same issue prevents classification and falls back to requiring
   prior evidence, restoring the deadlock D-77 is meant to remove. Classify the
   PR-owned change set from the merge base, while comparing genuinely touched
   evidence against current main for immutability. Do not weaken actual deletion
   or modification checks. Regression:
   `pr75_current_main_advance_does_not_delete_evidence`.

2. **[P2] The whitelist is recursive, unlike D-77's `reviews/*.md` scope.**
   `xtask/src/review_gates.rs:491` checks only a prefix and suffix. A valid-header
   file at `docs/requirements/reviews/nested/report.md` therefore passes the
   direct gate without prior evidence. The same predicate accepts `/./`, `/../`
   and doubled separators. The latter are predicate-level normalization defects,
   not demonstrated Git-tree traversal exploits: normal Git tree paths do not
   contain dot components. The nested path is a real end-to-end mismatch. This
   repository's own glob matcher distinguishes `*` (one component) from `**`
   (recursive). Require a canonical single filename after the exact reviews
   prefix, or obtain an explicit owner decision for recursive scope before
   changing D-77. Regressions:
   `pr75_classifier_rejects_nested_and_noncanonical_paths` and
   `pr75_nested_report_is_not_exempt_end_to_end`.

3. **[P2] Malformed Reviewed head values are silently truncated into valid SHAs.**
   The new check at `xtask/src/review_gates.rs:538` calls `is_sha` on the already
   parsed header, but `parse_header` at `xtask/src/review_gates.rs:100` first takes
   only 40 characters. Appending another hexadecimal digit, `not-a-sha` or
   `^{}` to an otherwise valid full SHA still passes direct validation. This
   does not validate the actual supplied field as the full SHA promised by
   D-77. Validate the complete field after explicitly allowed Markdown wrapping,
   without slicing an arbitrary value into validity. The parser behavior
   predates this diff, but the new direct acceptance path relies on it for its
   full-SHA guarantee. Regression: `pr75_rejects_malformed_sha_headers`.

4. **[P2] Present-but-empty required header fields pass direct validation.**
   `xtask/src/review_gates.rs:547` checks only whether `Triaged report` is `Some`,
   and `xtask/src/review_gates.rs:570` does the same for `Verdict`. The parser
   represents a blank value as `Some("")`. Consequently, an otherwise valid
   independent header with `- Verdict:` passes, as does a permitted triager
   header with `- Triaged report:` and no report at all. Check meaningful field
   content and recognized verdict syntax; a real **request changes** report must
   remain publishable, rather than requiring every publication to approve.
   Regressions: `pr75_rejects_empty_independent_verdict` and
   `pr75_rejects_empty_triaged_report`; the request-changes control passes.

5. **[P2] STATUS is exempted by pathname without requiring a document object.**
   At `xtask/src/review_gates.rs:506`, `git cat-file -e HEAD:path` establishes only
   object existence; at `xtask/src/review_gates.rs:524`, STATUS skips all further
   validation. An index entry with mode `160000` at
   `docs/requirements/STATUS.md`, pointing to a real commit, is therefore
   accepted as a review-document-only publication even though it is a gitlink,
   not a Markdown blob. Validate tree entry type/mode before granting the
   exception, including STATUS. This is an independent-review gate defect, not
   a claim that every other CI check accepts such a tree. Regression:
   `pr75_status_gitlink_is_not_a_document`.

## Coverage and policy interpretation

- Mixed changes containing actual code, non-`.md` review-directory files,
  mixed-case directory names, and renames crossing the allowed boundary are
  rejected. `changed_paths` uses `--no-renames`, so both source and destination
  are considered; the ordinary gate remains required for these cases.
- Actual content changes, deletions, renames and mode-only changes to review
  evidence already on main are rejected. New evidence need not approve its
  subject: request-changes reports are valid publications too.
- Including a regular STATUS document is an explicit D-77 policy exception,
  not an accidental whitelist expansion. It also admits STATUS-only PRs with
  no report to validate; the positive control confirms this. That is consistent
  with the allowed set as written, but it exempts any regular-file STATUS edit
  from independent review, not just a one-line publication summary. Restricting
  its content or requiring at least one new report would require an owner
  decision. Finding 5 concerns admitting non-documents, not that approved scope.
- D-77's direct-validation and existing-evidence immutability intent is reflected
  in the implementation, subject to the findings above. The recursive path
  behavior and malformed-header acceptance do not match its stated guarantees.
  D-77 says "full SHA references", not that every referenced object must exist
  locally; this review does not invent an additional object-resolution policy.
- **Existing integration limitation, not introduced by this diff:** the trusted
  `xtask/policy/review.toml` has no independent pairing for a Google author and
  an OpenAI reviewer. A correctly labeled report of this Gemini-authored PR is
  rejected with `code generation/google reviewed by independent code
  review/openai is not an allowed pairing`. The corresponding reproduction is
  `pr75_google_author_output_can_be_reviewed_by_openai`. D-51/team rule 2 requires
  verification of Google output by OpenAI; the policy needs an explicitly
  authorized alignment before this exact report can satisfy that pairing.
  Relabeling the author as Anthropic would be incorrect. This inherited mismatch
  is distinguished from the five implementation findings above.

```rust
mod common;

use common::{Repo, root};
use xtask::review_gates;
use xtask::util::Ctx;

const REVIEWS: &str = "docs/requirements/reviews";
const STATUS: &str = "docs/requirements/STATUS.md";

fn report(sha: &str) -> String {
    format!(
        "- Author role/provider: code generation / Anthropic\n- Reviewer role/provider: independent code review / OpenAI\n- Reviewed head: `{sha}`\n- Verdict: **approve**\n"
    )
}

fn setup() -> (Repo, String) {
    let repo = Repo::new();
    repo.write("README.md", "main\n");
    let main = repo.commit("chore: main");
    repo.git(&["checkout", "-q", "-b", "pr"]);
    (repo, main)
}

fn findings(repo: &Repo, main: &str, head: &str) -> Vec<xtask::util::Finding> {
    let ctx = Ctx {
        repo: repo.path().to_path_buf(),
        policy: root(),
    };
    review_gates::independent_review(&ctx, main, head).expect("gate")
}

#[test]
fn pr75_classifier_rejects_nested_and_noncanonical_paths() {
    let invalid = [
        "docs/requirements/reviews/nested/report.md",
        "docs/requirements/reviews/../payload.md",
        "docs/requirements/reviews/./report.md",
        "docs/requirements/reviews//report.md",
        "docs/requirements/Reviews/report.md",
        "Docs/requirements/reviews/report.md",
        "docs/requirements/reviews/report.MD",
        "docs/requirements/reviews/report.rs",
        "./docs/requirements/reviews/report.md",
        "docs/requirements/status.md",
    ];
    let accepted: Vec<_> = invalid
        .into_iter()
        .filter(|path| review_gates::is_review_document_path(path))
        .collect();
    assert!(accepted.is_empty(), "unexpectedly classified: {accepted:?}");
}

#[test]
fn pr75_nested_report_is_not_exempt_end_to_end() {
    let (repo, main) = setup();
    repo.write(&format!("{REVIEWS}/nested/report.md"), &report(&main));
    let head = repo.commit("docs: nested report");
    assert!(!findings(&repo, &main, &head).is_empty(), "nested path exempt");
}

#[test]
fn pr75_mixed_paths_and_renames_are_not_exempt() {
    for variant in ["code", "rename-in", "rename-out", "case", "non-md"] {
        let (repo, _) = setup();
        repo.write("source.txt", "source\n");
        let main = repo.commit("chore: source");
        repo.write(&format!("{REVIEWS}/report.md"), &report(&main));
        match variant {
            "code" => repo.write("src/lib.rs", "pub fn changed() {}\n"),
            "rename-in" => {
                repo.git(&["mv", "source.txt", &format!("{REVIEWS}/moved.md")]);
                repo.write(&format!("{REVIEWS}/moved.md"), &report(&main));
            }
            "rename-out" => {
                repo.git(&["add", "-A"]);
                repo.git(&["mv", &format!("{REVIEWS}/report.md"), "outside.md"]);
            }
            "case" => repo.write("docs/requirements/Reviews/other.md", &report(&main)),
            "non-md" => repo.write(&format!("{REVIEWS}/payload.rs"), "pub fn changed() {}\n"),
            _ => unreachable!(),
        }
        let head = repo.commit("chore: mixed change");
        assert!(!findings(&repo, &main, &head).is_empty(), "exempt: {variant}");
    }
}

#[test]
fn pr75_existing_evidence_cannot_change_or_disappear() {
    for variant in ["modify", "delete", "rename", "mode"] {
        let (repo, base) = setup();
        let original = format!("{REVIEWS}/original.md");
        repo.write(&original, &report(&base));
        let main = repo.commit("docs: original evidence");
        match variant {
            "modify" => repo.write(&original, &format!("{}\nchanged\n", report(&base))),
            "delete" => { repo.git(&["rm", "-q", &original]); }
            "rename" => { repo.git(&["mv", &original, &format!("{REVIEWS}/renamed.md")]); }
            "mode" => { repo.git(&["update-index", "--chmod=+x", &original]); }
            _ => unreachable!(),
        }
        let head = if variant == "mode" {
            repo.git(&["commit", "-q", "-m", "docs: mode"]);
            repo.git(&["rev-parse", "HEAD"])
        } else {
            repo.commit("docs: change existing evidence")
        };
        assert!(!findings(&repo, &main, &head).is_empty(), "accepted: {variant}");
    }
}

#[test]
fn pr75_rejects_malformed_sha_headers() {
    let mut accepted = Vec::new();

}
```
