## Confirmed findings

1. **High — coverage is not gap-free.** BOALF has five absent periods across four
   dates: 2024-03-14/21, 2024-07-08/27, 2024-09-22/29, 2024-11-03/23 and /24.
   Independent UTC interval-overlap checks find the same absences. Targeted live
   API queries returned HTTP 200 and zero records for all five on this review date.
   This does not establish that no balancing activity occurred. MID lacks one
   APXMIDP and 44 N2EXMIDP observations; full settlement-period union hides those
   provider gaps. Greenlink has 7,102 observations and 10,466 full-year absences in
   each of FUELHH and interconnector flows, including 6,704 absences between its
   first and last observations. Missing records must not be filled with zero.

2. **High — REMIT identifiers were mislabelled as outages.** Measured 48,191 raw
   rows, 15,638 distinct `mrid` values, 15,492 identifiers occurring in
   `UnavailabilitiesOfElectricityFacilities`, and 161 in `OtherMarketInformation`.
   These sets overlap, so they do not sum to the union. There is one exact duplicate,
   leaving 48,190 unique full payloads/message keys. There are 47,427 distinct
   `(mrid, revisionNumber)` pairs; that pair alone would incorrectly collapse real
   publications/asset records. 33,040 rows have revisionNumber greater than one.
   Publication windows cannot guarantee all outages overlapping 2024: messages
   initially published outside 2024 can be absent.

3. **Medium — reference and acceptance counts need qualified labels.** The BM
   reference endpoint is current, not a 2024 historical roster. It contains 3,134
   rows but 3,133 National Grid unit IDs (`WLNYO-4` has two rows), 3,054 non-null
   Elexon IDs (79 null rows), and 424 non-null EICs (2,710 null rows). The original
   retrieval time was not recorded. Do not invent it from filesystem timestamps.
   BOALF's 3,469,685 rows are acceptance profile segments, not that many distinct
   instructions; a separate streaming count finds 1,347,595 distinct
   `(nationalGridBmUnit, acceptanceNumber, acceptanceTime)` keys.

4. **Medium — verification tooling needed correction.** The partial patch loaded
   whole arrays and automatically replaced checksum baselines. Readers now stream
   JSON/gzip through the pinned ijson parser, existing indexes are verified by
   default, and index replacement requires `--refresh-checksums`. Report timestamps
   are preserved for reproducible reruns. Missing input directories fail before
   report writes. Cache validation and worker failure propagation are tested.

5. **Medium — licence attribution was incomplete.** Confirmed the published BMRS
   licence, including commercial use, the exact required Elexon attribution,
   onward sublicensing obligations, no endorsement/misrepresentation, and the
   personal-data/third-party-rights exclusions. Added the licence link and
   attribution to reports, provenance entries and usage notes. All 12 datasets
   retain the `open-commercial` provenance classification (D-56). MID remains
   labelled Market Index Price, consistent with D-57.

## Verification results

GNU `sha256sum --check --status` independently verified all 3,673 file hashes in the
12 original checksum indexes. Index filenames match the disk inventory exactly;
there are no duplicate index names, unlisted files or missing indexed files. Each
index digest matches the manifest. No original checksum index was changed.

Five focused tests pass for malformed JSON/gzip and error payload rejection,
byte/timestamp-stable cache reuse, invalid-cache replacement and temp cleanup,
concurrent worker failure propagation, checksum mismatch rejection and repeatable
reports. A scan of all changed source/document files found no private-key,
GitHub-token, AWS-access-key, hardcoded-credential, credential-in-URL or attribution
footer patterns. Manual inspection finds public unauthenticated endpoints only.

The audit uses `python -I`, two streaming workers, and daily duplicate-key sets
(month-spanning keys for REMIT). No raw captures or dependency binaries are added
to git. The original raw capture is retained, including its duplicate, to preserve
the existing hashes rather than invent or silently alter source data.

## Additional independent measurements

A clock oracle based on elapsed UTC time between consecutive Europe/London
midnights (rather than hardcoded clock-change counts) gives 364 × 48, 1 × 46 and
1 × 50 periods, totalling 17,568. The observed short-day IDs are consecutive
1–46; the original “1, 2, 5, …, 48” description was wrong. Autumn IDs are 1–50.

Streaming every gzip member to EOF also measured 44,372,024,793 uncompressed
bytes across the capture and 4,467,563,083 stored bytes: 89.93% total reduction.
The four gzip datasets alone occupy 2,858,231,566 bytes versus 42,762,693,276
uncompressed bytes: 93.32% reduction. The original “4.8 GiB total” was incorrect;
the stored total is 4.16 GiB. The corrected coverage text avoids mixing total
capture storage with the gzip-only reduction.

System buy and sell prices both range from −91.82 to 669.212 GBP/MWh; the PR's
669.21 upper bound is the correctly rounded two-decimal value.

The final strict verifier was also run on REMIT alone: it writes its findings
and exits 1 for the confirmed duplicate. A missing raw directory makes report
generation exit 2 before writing reports.

## Limits of retrospective verification

File hashes, inventories and full JSON/gzip parsing can be checked now. The
original claim that every download returned HTTP 200 cannot be reconstructed
without original transfer logs; only the targeted current API probes have
recorded HTTP statuses. The downloader writes JSON locally and gzip-compresses
four datasets itself; it does not preserve an API-supplied gzip representation.
Those unsupported historical transfer claims were removed from COVERAGE.md.

Zero duplicate **keys** depends on the following explicit definitions: date and
period for prices/demand; date, period and category for MID/FUELHH/flows; both unit
IDs, date, period and segment times for notifications, with notification time and
sequence for MEL/MIL and pairId for BOD; both unit IDs, acceptance number/time,
segment times and amendment flag for BOALF; Elexon ID, National Grid ID and EIC for
the reference; and mrid, revision, publication time, creation time and asset ID for
REMIT. Full logical payload equality is checked separately. Date-bound records
are checked against their file partition, so identical date-bearing rows cannot
hide across valid daily partitions. REMIT keys and payloads span all months.
