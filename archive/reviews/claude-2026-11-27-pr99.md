## Findings

### F1 (blocking): a missing or ambiguous author header bypasses the new same-vendor check
xtask/src/review_gates.rs:272-279. `author` is `None` in three cases: the Author line is missing, it names no known vendor, or it names two vendors. When it is `None`, `author.as_ref() != Some(&vendor)` is always true. Scenario: Claude writes a PR, and a Claude adversarial report omits the author line (or says `code generation / Anthropic and OpenAI`). The gate accepts that report. The independent path rejects the same header (line 240-241, "author role/provider missing or names no single vendor"). Fix: require `author` to be `Some`, add the missing and two-vendor cases to `d91_adversarial_vendor_differs_from_author`, and decide whether the gate should require the author vendor of the old Gemini reports on main (they all carry one).

### F2 (non-blocking): `google` still accepts new Gemini reports
xtask/policy/review.toml:41. The comment says Google is kept "only so existing Gemini reports keep counting". The gate does not enforce that. A new `adversarial review / Google` report would still pass. This is acceptable as a process rule under D-91, but it should be stated as a known gap, or the gate should limit Google to report files that already exist on main.

### F3 (non-blocking): stated author vendor is self-declared
The gate trusts the report header rather than the PR's real author. This was true before #99, and the trust model has not changed. The vendor rule now depends on that header more, so it is worth noting.

### F4 (non-blocking, scope): unrelated GPT spawn-agent instruction
AGENTS.md rule 11, team.md rule 8 and the review-round SKILL.md add the "Do not spawn sub-agents" GPT prompt rule, citing t3code#39101. D-91 does not cover it. It should be recorded as its own decision or cite one.
